# Cross-runtime vectors

Shared test data that keeps the three implementations of the display and HTML functions in
agreement: `bindc` (`src/core/display.rs`, canonical), the Rust runtime
(`runtime/bind-runtime`) and the JS runtime. Each implementation has a test that reads these
files and asserts equality.

Regenerate from the canonical implementation with
`BIND_BLESS=1 cargo test core::display` (bindc only), and commit the result.

## `html-trees.json`

An array of `{ "tree": <tree>, "html": <string> }`; `html` is what `render_html_value` /
`render_html` must produce for `tree`.

A `<tree>` is `{ "node": <name>, "args": [<arg>...], "children": [<tree>...] }`.

- `node` is the Bind name of a UI node: `UI` (the root), `Page`, `Container`, `Div`, `Grid`,
  `Stack`, `Header`, `Nav`, `Main`, `Section`, `Article`, `Aside`, `Footer`, `Paragraph`,
  `Span`, `Strong`, `Emphasis`, `Small`, `List`, `Item`, `Pre`, `Code`, `Heading`, `Link`,
  `Rule`, `Text` or `Empty`.
- an `<arg>` is a JSON string (a `String`) or `{ "int": "<decimal digits>" }` (an `Int`,
  canonical text, arbitrary size).
- `Text` has one string argument; `Empty` has none. `args` and `children` are always present.

## `numbers.json`

An array of `{ "bits": <16 hex digits>, "text": <string> }`: the IEEE-754 bits of an `f64`
and its ECMAScript `Number.prototype.toString` text (`js_number_to_string`). Bits are used so
`NaN`, `-0` and infinities are unambiguous.

The values were cross-checked against node (`String(x)` of the `f64` with those bits) and
agree on every case. The bindc test also fails when the committed file differs from the
generated case list (run with `BIND_BLESS=1` after changing the list).

## `pages.json`

An array of cases checked by the runtime test (and the JS runtime), hand-written from the
specification of the page shell and the error screen:

- `{ "kind": "page", "title", "description", "language", "stylesheet", "body", "html" }`:
  `page_html(meta, body)` (`pageHtml(meta, body)` in JS) must give `html`. `description` is a
  string or `null` (no meta description / og:description lines); every metadata value is
  HTML-escaped, the icon is written as is and `body` is inserted as is.
- `{ "kind": "error_body", "error", "message", "status", "html" }`: `error` is one of
  `BadRequest`, `NotFound`, `Internal`, `Overflow`, `RecursionLimit` with its `message`;
  `error_body(error)` must give `status` and `html` (`<main class="bind-error">` with the
  title of the status class and the public message, both escaped).
- `{ "kind": "bad_parameter", "name", "status", "html" }`: the error screen of a page
  parameter that is absent, repeated or invalid: the Rust runtime's
  `error_body(&bad_parameter(name))` and the JS runtime's `errorBody("BadParameter", name)`.

## `params.json`

Page parameters (Review Focus 1), checked by the Rust runtime (`QueryParams`, `param`,
`FromParam`, used by the SSR) and the JS runtime (`readParams` and its text decoders):

- `{ "kind": "text", "type", "text", "valid" }`: the text decoder of the Bind type `type`
  (`String`, `Int`, `UUID`, `Date`, `DateTime`, `Instant`) accepts `text` exactly when `valid`;
  an accepted text is canonical (the value shows and serializes as `text`).
- `{ "kind": "query", "query", "params": [[name, type]...], "values" | "error" }`: reading the
  parameters in order from the query string gives `values` (name to canonical text), or fails
  with `BadParameter` for the parameter `error` (absent, repeated, malformed `%` escape or
  invalid UTF-8 in its value, or rejected by its decoder).

## `temporal-order.json`

An array of `{ "type", "a", "b", "order" }`: two canonical wire texts (what chrono's serde
writes) of a `Date`, `DateTime` or `Instant` and their order, `<`, `=` or `>`. `bindc`'s
`compare_temporal` (used by `core::eval`) and the JS runtime's `compareDate`,
`compareDateTime` and `compareInstant` must give `order`; the Rust runtime's test reads both
texts with chrono and checks that chrono orders the values the same way (the generated Rust
compares chrono values) and that each text is canonical. The pairs are those where text order
is wrong or at a boundary: fractions (`…T10:00:00Z` vs `…T10:00:00.500Z`, `.500` vs
`.500001`), leap seconds, and extended or negative years (`+10000`, `-0001`). Generated by
`BIND_BLESS=1 cargo test core::display`.

## Fixture types of `collections.json` and `wire-rich.json`

Both files use these Bind declarations (`tests/codegen/collections.bd` declares them too, and the
generated snapshot crate checks `wire-rich.json` against its generated types):

```
enum class Cor { Z, A, M }            // wire names "z", "a", "m"; order Z < A < M
distinct type Nota = Decimal          // wire: the Decimal string; order: by value
distinct type Codigo = UUID
data class Ponto(val x: Int, val y: Int)
data class Pagina<T>(val itens: List<T>, val total: Int)
sealed class Forma {
    data class Circulo(val raio: Int)                       // {"circulo": {"raio": …}}
    data class Retangulo(val largura: Int, val altura: Int) // {"retangulo": {…}}
    data object Vazia                                       // "vazia"
}
```

Every value is written in its `bind-json` form: `Int` and `Decimal` as strings (`"10"`,
`"1.50"`), `Boolean` as `true`/`false`, `String`, `UUID`, `Date`, `DateTime`, `Instant` as their
canonical strings, enum variants by their wire names.

## `collections.json`

The `Set`/`Map` builtins and the canonical order (the reference evaluator `core::eval` is the
oracle; see `docs/type-system.md`, "`Key`"), checked by the Rust runtime
(`runtime/bind-runtime/tests/collections.rs`) and the JS runtime. An array of cases:

- `{ "kind": "set", "element", "setOf", "steps", "toList", "contains" }`: `element` is the
  element type (`Int`, `Decimal`, `Nota`, `String`, `Boolean`, `Cor`, `Date`, `DateTime`,
  `Instant`, `UUID`). Start from `setOf(<setOf items>)` (`emptySet()` when `setOf` is `[]`),
  then apply each step in order: `["insert", x]` or `["remove", x]`. `toList` of the result
  must be `toList`, exactly (texts included: of two equal elements the first one inserted stays,
  so `setOf("1.00", "1.0")` keeps `"1.00"`); `setSize` is its length; the set's wire form is
  the same array; each `[x, expected]` of `contains` gives `contains(s, x) == expected`.
- `{ "kind": "map", "key", "steps", "entries", "lookup" }`: `key` is the key type (as above);
  values are `String`s. Start from `emptyMap()` and apply each step: `["put", k, v]` or
  `["removeKey", k]`. The map's wire form must be `entries` (`[key, value]` pairs in canonical
  key order); `keys` and `values` are its first and second columns, `mapSize` its length; each
  `[k, expected]` of `lookup` gives `lookup(m, k)` (`null` when absent).

Ruling A: `put` on an equal key keeps the existing key (and its text) and replaces the value;
`insert` of an equal element keeps the existing one; `setOf` inserts left to right; removing an
absent element or key changes nothing. `Decimal` keys compare by value (`1.0` = `1.00`,
`-0` = `0`); strings by code point (so `"！"` (U+FF01) < `"😀"` (U+1F600), unlike UTF-16 order);
temporal values by time, never by text; enum variants by declaration order.

## `wire-rich.json`

JSON round trips and malformed inputs of the rich wire types, checked by the Rust runtime
(`tests/collections.rs`: the RPC request decoder, the response encoder and the SSR in-memory
round trip), by the generated snapshot crate, and by the JS runtime. An array of
`{ "type", "json", "valid", "canonical"? }`: `type` is a Bind type over the fixture types
(`Set<Int>`, `Set<Decimal>`, `Set<String>`, `Set<Cor>`, `Set<Instant>`, `Map<String, Int>`,
`Map<Decimal, String>`, `Map<Cor, Int>`, `Map<Int, Set<Int>>`, `Result<Int, String>`, `Forma`,
`Pagina<Int>`, `Pagina<Ponto>`, `Map<Codigo, Pagina<Ponto>>`). When `valid` is `true`, decoding
`json` succeeds and encoding the value gives `canonical` (sets sorted, maps' pairs sorted by key,
record fields in declaration order). When `valid` is `false`, decoding fails: duplicate set
elements or map keys (by value: `["1.0", "1.00"]` is a duplicate), malformed pairs (`[["a"]]`,
`[["a", "1", "2"]]`, `[[]]`, an object instead of a pair), an object instead of an array, an
unknown variant tag or a wrong-case one, a variant with fields written as a bare string, a
missing or extra field, `Result` objects with zero or two keys or a lowercase tag.

## Links

`html-trees.json` includes the `Link` href allowlist cases: after trimming characters
<= U+0020 and removing tab/LF/CR, a URL with a scheme is emitted only for `http`, `https`,
`mailto`, `tel` (case-insensitive); otherwise the `href` is `""`. URLs without a scheme are
emitted as is.

## JS runtime only: `Decimal` and `f32`

`runtime/bind-runtime-js/tests/decimal-vectors.json` and `f32-vectors.json` are generated from
`rust_decimal` and Rust's `f32` by `runtime/bind-runtime/tests/js_vectors.rs`, which fails when
the committed files differ from the generated content (regenerate with
`BIND_BLESS=1 cargo test --manifest-path runtime/bind-runtime/Cargo.toml --test js_vectors`).
They live next to the JS tests because only the JS runtime reimplements these operations.
